GLB Lab @VERSION@

Checks a 3D glTF/GLB model for things that page and document checkers (such as axe-core for web pages or PAC for PDF) are not designed to examine: whether its parts have meaningful names, whether labels are drawn as geometry instead of text, whether the role colours remain distinguishable under simulated colour vision deficiency, and whether they have enough contrast. The model is read in this browser and is not uploaded anywhere; the page works offline.

3Closest role pairs under simulated colour vision deficiency

The five pairs with the smallest colour difference ΔE₀₀ for each type of vision, after the Machado et al. (2009) simulation of the “Result” colours.

4Contrast between roles

WCAG 2.2, success criterion 1.4.11, asks for 3:1 between a graphical part and the colours next to it. The tool cannot know which roles touch on screen, so it lists every pair below 3:1: check those that are adjacent, or separate them with an outline, pattern or label.

5Part names, text as geometry and descriptions

A screen reader can announce a part only if the model or the viewer gives it a name. Names such as “Cone002” or “VMtl003” are generated by the software and convey nothing. Letters modelled as geometry (e.g. “σ”, “π”, “H”) are invisible to assistive technology and need a text equivalent. We recommend extras.a11y = {"label", "description"} on each part.

About, method and citation

Method

  • Colour of a part. The material’s baseColorFactor (linear in glTF 2.0) is converted to sRGB. Lighting, shadows, specular highlights, tone mapping, textures and vertex colours are not modelled, so the values describe material colours, not every pixel. Panel 6 lists what this model contains beyond that.
  • Opacity. Used only for alphaMode BLEND, as in glTF 2.0. Blending α·colour + (1−α)·background is computed either on 8-bit sRGB values (as WebGL does in its default, sRGB-encoded drawing buffer) or in linear light (as with a linear render target).
  • Contrast. WCAG 2.2 relative luminance and contrast ratio; the 3:1 criterion is that of success criterion 1.4.11, Non-text Contrast.
  • Colour vision deficiency. Machado, Oliveira & Fernandes (2009) matrices applied in linear sRGB, with linear interpolation between the published severities (steps of 10%). Out-of-gamut results are clipped. A simulation is a model of average dichromatic or anomalous vision, not of a particular person.
  • Colour difference. CIEDE2000 (kL = kC = kH = 1) on CIELAB from sRGB, D65, 2° observer, implemented according to Sharma, Wu & Dalal (2005). The threshold is exploratory.
  • Names and text. A part has a software-generated name when its node name is empty or matches common generated patterns (Cone002, Circle09-FACES001, VMtl003, PART1_5 …). Text as geometry: a geometry-bearing node whose own, mesh or parent name starts with “Text” (3ds Max text shapes; the exporter may name their mesh PARTn_m). Both are heuristics for models from 3ds Max and similar software; check the list of parts.
  • Numerical core. CVD Lab 2.1 (Georgios Korakakis), included unchanged; panel 8 tests it.

The tool is neither a diagnosis nor proof that a model is understandable. It shows where to look.
